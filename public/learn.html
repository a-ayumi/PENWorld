PULSAR のしくみ図鑑

机の上の液晶ペット「PULSAR」が、どんな部品で・どんな順番で動いているかを、うごく図と 本物のコードで たどるページです。図は さわって動かせます。コードの断片は リポジトリ a-ayumi/PENWorld の 実際のファイルから 抜き出しています（読みやすく 少し 省略）。

1全体の地図

PULSAR は TypeScript + Three.js で書かれた Web アプリ（PWA）です。大きく分けると「本体の 3D 模型」と、その液晶に映る「箱庭（World）」の 2 層になっています。箱庭は 毎コマ 小さな画面（480×480）に描かれ、その絵が 本体の液晶の テクスチャ として 貼りつけられます。

箱に カーソルを のせる（スマホは タップ）と、その部品の 役わりが 下に 出ます。

main.ts から 読んでいくのが おすすめです。

World は「役わりごとの ファイル」に 分けてある

World は とても大きなクラスなので、メソッドの中身を parts/ の 6 ファイルに 分け、クラスの頭で つなぎ合わせています。JavaScript の this の しくみを 使った 書き方です。

// src/world/parts/village.ts — 関数の 1 番目の 引数に this の 型を 書く
export function townEra(this: World): Era {
  return eraOf(eraStep(this.vScore), this.eraPath[this.stageIndex])
}

// src/world/World.ts — クラスの 頭で「メソッド」として つなぐ
import * as Vi from './parts/village'
export class World {
  townEra = Vi.townEra   // world.townEra() と 呼べる
}

ファイルを 分けても「world.○○()」という 呼び方は かわりません。大きくなった クラスを 読みやすく 保つ 工夫です。

21 コマの流れ（ゲームループ）

ブラウザは 1 秒に 約 60 回、setAnimationLoop の 関数を 呼びます。そのたびに「世界を少し進める（update）」→「絵を描く（render）」を くり返します。下の図の ▶ で 1 コマを ゆっくり 再生できます。

dt（前のコマからの 秒数）は 1/20 秒までに おさえる。タブが 裏に 回っている間は 止める。
// src/main.ts（ようす）
renderer.setAnimationLoop((t) => {
  if (document.hidden) return          // 見えていない時は 何もしない
  const dt = clamp(timer.getDelta(), 0, 1 / 20)
  world.update(dt)                           // 生き物・町・天気を すすめる
  world.render(renderer)                     // 箱庭を 480×480 に 描く → 仕上げ
  renderer.render(scene, camera)              // 本体と 机を 描く（液晶に 箱庭の 絵）
})

3生き物の頭の中（状態マシン）

モンスター 1 匹ずつが「いま 何をしているか」を 1 つの 状態（state） として 持ちます。状態ごとに 決まった動きをし、時間が来たり 目的を果たしたりすると think() が 次の状態を えらびます。ゲームの AI で いちばん よく使われる、わかりやすい しくみです。

スライダーを 動かして think() を 押すと、どの状態に 移るかが 光ります。

// src/world/parts/creatures.ts の think()（とても 短く した もの）
if (c.hunger < 45 && food) return setState(c, 'seek')     // 食べ物へ
if (c.energy < 25 || night)  return setState(c, 'sleep')    // ねむる
if (site)                     return setState(c, 'gather')   // 資材を ひろって 建設現場へ
return setState(c, Math.random() < 0.5 ? 'wander' : 'idle')

4道さがし A*（エースター）

箱庭の地面を 0.5 マスの 升目に区切り（nav.ts の NavGrid）、木・家・水・急な崖を「通れない」と しるします。目的地へは A* という 方法で 道を さがします。「ここまでの 道のり + ゴールまでの 見こみ」が 小さい 升目から 順に しらべていく のが ポイントです。

升目を なぞると かべ（通れない 所）を 描けます。緑 = スタート、赤 = ゴール、うすい色 = しらべた 升目、オレンジ = 見つかった 道。
// src/world/nav.ts（考え方）
open = [start]                        // これから しらべる 升目
while (open.length) {
  cur = open の中で f = g + h が いちばん 小さい 升目
  if (cur === goal) return 道を たどって かえす
  for (となりの 8 マス) {
    if (通れない || 段差が CLIFF(0.75) より 高い) continue
    g2 = g[cur] + 歩く 長さ               // ここまでの 道のり
    if (g2 < g[next]) { g[next] = g2; from[next] = cur; open に 入れる }
  }
}

本物では「まっすぐ 行ける時は さがさない」「1 コマに 6 回まで」など、重く ならない 工夫も しています（moveTo()）。

5町が育つ しくみ

町は 2 つの 数で 育ちます。区画：家は 町の まんなかから 外へ、輪を 1 つずつ ひろげて 空いた 場所に 建つ（townLot()）。時代：家と建物の 点数（vScore）が ふえると、のじゅく → 丸太 → 木組み → 石 → 城 → … と 時代が すすみ、まんなかから 新しい 形に 建てかわる。

点線の 円 = 区画の 輪。色 = その家が 建った 時代。外れの 家は 年を とると 灰色（くずれた 姿）に なる。
// src/world/eras.ts — 点数 → 段 → 時代（6 段めで 枝わかれ）
const STEP_SCORE = [0, 1, 3, 6, 10, 15, 21, 28]
export function eraOf(step, path) {
  if (step <= 5) return step                    // のじゅく … 城
  if (path === 'white') return 6              // 白い城
  return Math.min(9, step + 1)                 // じょうき → まざり → きかい
}

6城壁の 年輪

町が 育つと 住民が まわりを へいで 囲みます（growRings()）。家が へいの 外に はみ出すと、もっと 外に 新しい 輪を 引きます。内がわの 古い 輪は のこって 古び、くずれて 通れる すきまが できます。木の 年輪の ような 入り組んだ 町に なります。

門は いつも マップの まんなかの 向き。門から まんなかまでは 家を 建てない（大通り）。

7つなぎ目なしの 大きな世界

大きな世界は、森・砂丘・雪原 など 9 つの 地方を 3×3 に ならべた ものです。地方ごとの「高さの 式」を そのまま 使い、さかいめの 近く（はば 7）では となりの 地方の 高さと 重みを つけて まぜます。山は となりの 山と つながり、地面の 模様も 升目ごとに すこし ゆらして まだらに まぜるので、まっすぐな 線が 出ません。

横に 2 つの 地方を ならべた 断面。点線 = それぞれの 地方の 高さ、太線 = まぜた 高さ。はばを 0 に すると 崖の ような 段差が 出ます。
// src/world/worldmap.ts（ようす）
const weight = (tile, x, z) => smooth(BLEND, -BLEND, さかいめからの 距離)
const heightAt = (x, z) => {
  let sum = 0, wsum = 0
  for (const t of tiles) { const w = weight(t, x, z); sum += t.heightAt(x, z) * w; wsum += w }
  return sum / wsum                            // 重みつき 平均
}

8見た目の 仕上げ（ピクセル・ジオラマ）

3D の 箱庭を わざと 小さな 画面（480×480）に 描き、そのあと diorama.ts の シェーダーで「色を くすませる → 色の 段を へらす → 網点（ディザ）で つなぐ → 奥行きの さかいに 輪郭」を かけます。最後に 2 倍に 拡大して、ドットが 正方形に 並ぶ 絵に しています。

9重さ対策（見た目を 落とさずに）

形を まとめる

家 1 けんは 百を こえる 小さな 箱で できています。描く 回数（ドローコール）が 多いと 重いので、同じ色の 箱は 1 つの 形に まとめます（Kit.done() / mergeByColor()）。

材質を 使い回す

同じ色の 材質は 1 つだけ 作って みんなで 使います（sharedLam()）。作りなおす たびに 新しく 作ると、捨て忘れた 分が メモリに たまって いきます。

読みこみ範囲

見ている 所から 遠い 地方は 描かない（Stage.cull()）。引いて 見るほど 広く 描きます。

止める・まびく

タブが 裏に 回ったら 止める。60 秒 さわらないと 30fps。HUD の 文字は 1 秒に 30 回まで。画質「低」では 草・粒・水の きらめきを へらす。
