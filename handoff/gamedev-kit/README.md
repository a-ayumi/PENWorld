# ゲーム作り知恵袋（gamedev-kit）

PULSAR（Three.js + TypeScript の「3D の液晶ペット + ドット絵の箱庭」）を AI エージェントと 2 週間ほどかけて作った経験を、
**別の AI ツール（Antigravity など）で次のゲームを作る時にそのまま使える形**にまとめたものです。

PULSAR そのものの説明書ではありません。「進め方・確かめ方・見た目の作り方・ゲームの仕組みの作り方・失敗」を、
どのゲームにも持っていける形で書いています。コードの実例は PULSAR のリポジトリ（`a-ayumi/PENWorld`）にあります。

## いちばん大事な 10 か条（ここだけ読めば だいたい足りる）

1. **AI へのルールの紙（AGENTS.md / CLAUDE.md）と計画の紙（PLAN.md）を最初に作る**。機能を足したら 1 行足す。会話が切れても紙から再開できる。
2. **1 PR = 1 テーマ。出した PR にあとからコミットを足さない**（足す前にマージされて「入ってない」が 3 回起きた）。追加は新しい PR。
3. **見本を 1 つ作る → 見てもらう → 広げる**。全部作ってから「ちがう」が一番高くつく。
4. **見本（動画・画像）は言葉にばらしてから作る**。「この感じ」のままでは作れない。コマを切って、色・光・線・質感・密度に分ける。
5. **目で見る前に数で見る**。早送りして数える（何回食べたか・何分で勝ったか・行けない升目は何個か）。
6. **テストの早送りがうそをつくことがある**（1 歩を大きくすると物が着地しない等）。おかしな結果は、ふつうの歩幅でも測りなおす。
7. **報告は「変えたこと → 確かめたこと → 確かめていないこと → つぎ」**。撮っていない・遊んでいないことは、そう書く。
8. **重い効果は必ず切りかえられるように（画質 高 / 低）**。スマホは熱くなる。描く回数とフレーム数を測る。
9. **デザインはオリジナル**。雰囲気・技法だけ取り入れ、形・キャラ・ロゴはまねしない。
10. **公開リポジトリには秘密を入れない**。外への通信を増やさない。読みこんだセーブは信用せず検査する。
